No redux tradicional, a imutabilidade é o princípio de preservar o estado anterior durante uma atualização e produzir uma nova estrutura com os valores modificados. Em vez alterar diretamente um objeto ou uma lista existente, o reducer retorna uma nova versão do stado. Esse comportamento é fundamental para manter o fluxo de dados previsível e permite que o redux e o react identifiquem mudanças nas referências dos objetos.

O spread operator é um recurso do javascript amplamente utilizado para realizar essas atualizações. Ele permite copiar as propriedades enumeráveis de um objeto ou os elementos de um array para uma nova estrutura. Dessa forma, é possível preservar os dados existentes e modificar apenas as partes necessárias para representar o próximo estado.

Quando um reducer precisa atualizar uma propriedade de um objeto, a ideia é manter as demais propriedades e substituir somente o valor correspondente à alteração. Isso evita que informações não relacionadas sejam perdidas durante a atualização. Em aplicações corporativas, nas quais o estado pode reunir os dados de uma entidade, filtros, indicadores de carregamento e mensagens de retorno, preservar as propriedades que não precisam mudar é especialmente importante.

Entretanto, a imutabilidade não se limita ao objeto principal. Quando o estado possui estruturas aninhadas, como objetos dentro de objetos ou listas de entidades, cada nível que precisa ser atualizado deve receber uma nova referência. Copiar apenas o objeto externo não torna imutáveis as estruturas internas que continuam sendo compartilhadas com o estado anterior. Por isso, alterações em propriedades aninhadas exigem a criação de novas estruturas nos níveis afetados, preservando as demais informações.

O mesmo princípio se aplica aos arrays. Operações como inclusão, remoção ou atualização de registros devem produzir uma nova lista, sem modificar diretamente a lista original. O spread operator pode ajudar a construir essa nova estrutura, combinado com outras operações de javascript apropriadas para cada situação. A escolha depende do tipo de transformação que o reducer precisa realizar.

É importante compreender que o spread operator realiza uma cópia superficial, também conhecida como shallow copy. Isso significa que ele copia as propriedades ou os elementos para uma nova estrutura, mas não duplica recursivamente todos os objetos internos. Se uma propriedade contém outro objeto, a nova estrutura inicialmente mantém uma referência para esse objeto interno. Portanto, modificar diretamente uma estrutura aninhada compartilhada ainda pode alterar dados associados ao estado anterior.

Essa distinção é relevante porque o redux depend da previsibilidade das transições de estado. Quando o estado anterior é preservado e as partes modificadas recebem novas referências, torna-se mais fácil identificar o que mudou, comparar estados e evitar efeitos inesperados em outros componentes.

Em reducers clássicos baseados em switch-case, o spread operator aparece frequentemente dentro dos casos responsáveis pelas atualizações. Cada caso recbe uma action, utiliza os dados do payload e retorna uma nova estrutura que representa o estado atualizado. O reducer continua sendo responsável por decidir qual transformação deve acontecer, enquanto o spread operator oferece uma maneira prática de construir o resultado sem alterar diretamente os dados recebidos.

Assim, a imutabilidade define a regra de atualização, e o spread operator é uma ferramenta para aplicá-la. Compreenedr essa relação é essencial para interpretar reducers legados, preservar dados não relacionados à operação e manter o comportamente da store consistente ao longo da publicação.
