No redux tradicional, o action.payload é o mecanismo utilizado para transportar os dados necessários para que o reducer consiga uma alteração no estado. Enquanto o action.type identifica qual evento aconteceu, o payload contém as informações associadas a esse evento. Essa separação permite que uma mesma estrutura de action represente tanto a intenção da operação quanto os dados necessários para executá-la.

O conteúdo do payload não possui um formato obrigatório definido pelo redux. Ele pode representar um valor simples, um objetivo, uma lista ou uma estrutura mais complexa, dependendo da necessidade daquela funcionalidade. O importante é que o reducer conheça o formato esperado e utilize essas informações para produzir o próximo estado.

Em uma aplicação tradicional, por exemplo, uma action relacionada ao carregamento de uma entidade pode transportar os dados retornados pela API no payload. O reducer recebe essa action, identifica seu type e, dentro do respectivo caso, utiliza o conteúdo do payload para preencher ou atualizar determinada propriedade do estado. Dessa maneira, o reducer não precisa realizar a requisição ou conhecer os detalhes da API. Ele apenas recebe os dados que chegaram e determina como eles devem ser incorporados à store.

O payload também pode carregar informações utilizadas em operações mais específicas. Uma action de atualização pode transportar a entidade modificada, uma action de remoção pode tranportar o identificador do registro, uma action relacionada a filtros pode transportar os novos valores selecionados pelo usuário. Em todos esses casos, o payload representa os dados que acompanham a itenção descrita pelo type.

Essa separação é especialmente importante porque mantém responsabilidades diferentes dentro do fluxo do redux. A action descreve o acontecimento e transporta seus dados, enquanto o reducer interpreta essas informações e calcula o novo estado. O reducer não deve alterar o payload nem executar efeitos colaterais sobre ele. Seu papel é utilizar os dados recebidos para produzir uma nova representação do estado.

Também é importante observar que o formato do payload precisa ser consistente entre quem dispara a action e quem a trata. Se uma action espera receber determinado conjunto de informações, o reducer precisa saber exatamente onde esses dados estarão dentro do payload. Em aplicações grandes, uma estrutura inconsistente pode dificultar a manutenção e gerar erros difíceis de rastrear, principalmente quando diferentes ducks trabalham com padrões distintos.

No padrão ducks, esse relacionamento fica concentrado dentro do próprio módulo da funcionalidade. As actions que definem quais informações são enviadas, enquanto o reducer define como essas informações alteram o estado daquele domínio. Ao analisar um fluxo redux legado, identificar o type e o conteúdo do payload permite entender não apenas qual evento aconteceu, mas também quais dados foram enviados para que o estado pudesse ser atualizado.

Assim, o action.payload funciona como a ponte entre a interação representada pela action e os dados utilizados pelo reducer. O type responde ao "o que aconteceu", enquanto o payload responde ao "quais dados estão relacionados a esse acontecimento."
